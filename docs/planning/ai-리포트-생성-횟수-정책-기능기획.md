## 0. 착수 배경

하루에 질문이 하나만 제공되어 사용자가 한 달에 새로 쌓을 수 있는 답변은 최대 약 28~31개다. 리포트 한 건은 현재 연차의 답변 중 최소 10개, 최대 15개를 사용한다. 따라서 생성 횟수를 단순히 캘린더 월 기준으로 제한하면, 이미 데이터 공급량으로 자연스럽게 제한되는 서비스 특성을 충분히 반영하지 못하거나 같은 답변의 반복 분석을 유도할 수 있다. AI 비용을 통제하면서도 사용자가 의미 있게 달라진 결과를 받을 수 있는 생성 기준과 한도를 다시 정한다.

### 기존에 확정되어 재론하지 않는 항목

- 하루 하나의 질문·답변 구조
- 리포트 생성 시 현재 연차 답변 10~15개를 사용자가 직접 선택
- 현재 리포트 종류는 2개이며 향후 추가될 수 있음
- 리포트 생성·쿼터 판정은 서버가 담당
- 생성 실패는 횟수를 차감하지 않음
- 생성된 리포트는 본인만 영구 열람

### 재검토 대상

- 제한의 주목적: 비용 보호, 결과의 새로움, 수익화 중 무엇을 우선할지
- 제한 단위: 캘린더 월, 새 답변 누적, 사용한 답변 조합 또는 혼합형
- 리포트 종류별/사용자 통합 쿼터 여부
- 최초 생성, 재생성, 실패, 동시 요청의 차감 규칙
- 결제 전 정책과 구독 도입 후 정책의 관계

## 1. 문제 정의

- **주 타깃**: AI 리포트를 체험하려는 무료 사용자와, 반복적으로 자기 기록을 분석하려는 구독 사용자
- **해결하는 문제**:
  - AI 리포트가 무제한 생성되면 호출 비용을 통제할 수 없다.
  - 무료 사용자와 구독 사용자의 생성 권한 차이가 없으면 리포트를 구독 가치로 전환하기 어렵다.
  - 반대로 새로운 답변만 사용하도록 강제하면 사용자가 중요하게 여기는 기존 질문·답변을 다시 해석할 자유를 잃는다.
- **목표 우선순위**:
  1. 무료/구독 플랜별 생성 권한 차이를 만들어 향후 수익화에 연결한다.
  2. 모든 플랜에 절대 생성 상한을 두어 AI 비용과 비정상 반복 요청을 막는다.
  3. 사용자는 이전 리포트에서 사용한 질문·답변을 새 리포트에서도 자유롭게 재사용할 수 있다.
- **배제된 정책**: 직전 리포트 이후 새 답변 N개를 필수 조건으로 삼거나, 한 번 사용한 답변을 소진 처리하는 방식
- **성공 기준**:
  - 무료 사용자가 AI 리포트의 가치를 충분히 체험한 뒤 추가 생성에서 구독 필요성을 이해한다.
  - 구독 사용자는 새 답변과 기존 답변을 원하는 조합으로 반복 분석할 수 있다.
  - 서버가 플랜과 리포트 종류별 절대 상한을 일관되게 판정하여 예상 밖 AI 비용을 막는다.

### 제한 모델 비교 (횟수제로 확정)

#### A. 플랜·리포트 종류별 횟수제 — 채택

- 무료: 모든 리포트 종류를 합쳐 총 2회
- 유료: 리포트 종류별 월 2회(현재 2종 기준 월 최대 4회)
- 장점: 사용자가 남은 횟수를 바로 이해하고, 현재 2종의 리포트를 운영하기 단순하다.
- 단점: 리포트 종류가 추가되면 유료 사용자의 총 제공량과 AI 비용이 자동으로 증가한다. 리포트별 실제 생성 비용 차이를 반영하기 어렵다.

#### B. 사용자 노출 크레딧제

- 예시: 무료 최초 100크레딧, 유료 매월 300크레딧 / A 리포트 100, B 리포트 50 차감
- 장점: 리포트별 실제 비용·가치 차이를 반영하고, 향후 리포트 종류 추가나 크레딧 추가 구매에 유연하다.
- 단점: 잔액, 차감 단위, 갱신일, 이월·소멸, 환불·실패 복구 정책이 모두 필요하다. 차분한 자기기록 서비스에서 포인트 계산 경험이 앞에 드러날 수 있다.
- 결정: 이번 범위에서 도입하지 않는다.

#### C. 내부 가중치 + 사용자에게는 횟수 표시

- 서버는 리포트별 비용 단위를 관리하되, 앱은 `이번 달 A 2회 / B 2회`처럼 단순하게 안내한다.
- 장점: 사용자 경험을 단순하게 유지하면서 비용 정책을 조정할 수 있다.
- 단점: 공용 크레딧 풀처럼 자유롭게 선택하는 구조는 아니며, 내부 가중치가 실제 제한에 영향을 주기 시작하면 사용자 안내와 서버 판정이 불일치할 수 있다.
- 결정: 이번 범위에서 도입하지 않는다.

### 확정 방향

- 현재 2종 출시 시점에는 A의 리포트 타입별 횟수제로 시작한다.
- 아래 조건 중 하나가 생기면 크레딧제를 별도 재검토한다.
  1. 세 번째 리포트 종류를 출시한다.
  2. 리포트 종류별 평균 AI 원가 차이가 운영상 무시하기 어려운 수준으로 확인된다.
  3. 구독 외 크레딧 추가 구매를 상품화한다.
- 크레딧을 도입하더라도 잔액과 차감은 서버를 진실원으로 관리한다.
