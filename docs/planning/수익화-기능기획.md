- 작성일: 2026-07-06 / 상태: 확정 (가격 등 오픈 이슈 3건 제외)
- 연관 문서: (추후 추가)

## 0. 착수 배경

- 요청: "수익화를 위해 어떤 기능을 더 추가해야 할지 고민" — 기능 아이디어 자체가 미정이며, 방향 결정부터 시작한다.
- 현재 앱 상태:
  - 하루 한 질문에 답하며 나를 기록하는 앱. 홈(오늘의 질문+타임라인) / 피드(공개 답변) / 설정 3탭
  - 현재 수익원은 AdMob 배너 + 전면 광고가 유일
  - AI 분석 "나를 만나는 시간" 기능이 클라이언트 단 완성, 서버 연동 대기 중 (유료 전환 후보 자산)
  - 인앱 결제(IAP) 인프라는 아직 없음

## 0.5 방향 결정 (확정)

- **수익화 방향: 프리미엄 구독** — 광고 제거 + AI 분석 심화 리포트 + 기록 기능 확장을 묶은 월/연 구독
- 검토했던 대안: AI 리포트 단건 구매, 리워드 광고 확장, 실물/굿즈 전환 → 모두 이번 범위에서 제외
- **IAP 인프라 도입 확정.** 처음엔 회피 의사였으나, 구독은 스토어 정책상 IAP 필수임을 확인 후 감수하기로 결정. RevenueCat 등 구독 관리 SDK 활용을 전제로 부담 최소화
- 가격대는 미정 (예시로 월 3,900원 / 연 29,000원 수준을 논의 출발점으로)

## 1. 문제 정의 (확정)

- **주 타깃**: 자기이해 추구층 — 기록량과 무관하게 "AI가 나를 분석해준다"는 경험 자체에 끌리는 사용자. 신규 유입 직후부터 전환 가능하지만 분석 재료(답변 데이터)가 적다는 특성 있음
- **해결하는 문제**: 앱의 수익원이 AdMob 광고뿐이라 수익 규모에 상한이 있음. 지불 의사가 있는 사용자에게 팔 수 있는 가치가 없음
- **성공 기준**: 구독 전환율 (MAU 대비 유료 구독자 비율). 자기기록 앱 일반 벤치마크 1~3% (구체 목표치·측정 기간 → 오픈 이슈 2번)
- **기존 무료 기능은 그대로 유지.** 구독은 새 가치만 판매. 기존 사용자 반발 방지가 원칙

### 근거 출처 구분 (사용자 질의로 명시)

- "구독" 방향: 사용자 선택
- "AI 분석을 구독의 핵심 가치로": AI 분석 기능(클라 완성, 서버 대기)이 이미 존재한다는 프로젝트 이력 + 자기기록 앱 업계 패턴에 근거한 **제안(가정)** → 아래 질문으로 확정 필요

### 구독 혜택 구성 (확정)

1. **AI 분석 심화 리포트** — 기존 "나를 만나는 시간" 자산을 유료 핵심 가치로 승격
2. **광고 제거** — 구독자는 배너·전면 광고 미노출
3. **테마·꾸미기** — 앱 아이콘, 컬러 테마 등 감성적 커스터마이징
- 제외: 과거 질문 다시 받기 (→ Won't)

2. **[주] 유지**: 구독자가 / 새 기록이 충분히 쌓였을 때 "새 분석을 만들 수 있어요" 알림을 받고 / 앱에 돌아와 분석 종류를 골라 리포트를 생성·열람하며 / 구독을 갱신할 이유를 얻는다 (※ 리포트는 자동 발행이 아니라 사용자 직접 요청 — 4단계 결정으로 수정됨)

4. **[부] 복원**: 기존 구독자가 / 기기 변경·재설치 후 / 구매 복원을 실행해 / 혜택을 되찾는다

- **Must**: IAP 인프라(구매·복원·페이월, RevenueCat 전제) / AI 리포트 서버 연동+심화 버전 / 무료 리포트 1회 로직 / 구독자 광고 제거 / 설정 내 구독 상태 표시

## 4. 상세 정책 (확정)

### 4.1 AI 분석 리포트

- **리포트 종류 기반** (월 단위 발행 아님). 현재 2종: **사고패턴 분석**, **따뜻한 회고**. 종류는 추후 확장 가능
- **생성 방식**: 사용자가 직접 요청. 종류 선택 → 분석할 기록을 **직접 선택** (최소 10개 ~ 최대 15개)
- **최소 조건**: 선택 가능한 기록이 10개 미만이면 생성 불가, "기록이 더 필요해요" 안내
- **재생성**: 같은 종류라도 재생성 가능. ~~단 구독자 월 생성 한도 10회~~ → **⚠️ 2026-08-03 대체**: 구독자 한도는 종류당 월 2회로 변경 (`ai-분석-리포트-이용정책-기능기획.md`)
- ~~무료 사용자: 평생 통합 1회 (종류 무관) 무료 생성. 이후 페이월~~ → 결제 전 임시로 종류당 월 2회 무료 (동 문서 주제 1)
- 무료 1회 차감은 생성 "성공" 시점. 생성 실패(서버 오류) 시 차감하지 않음 (확정)
- **권한**: 리포트는 생성한 본인만 열람. 공유·공개 없음
- **만료 후 접근**: 구독 중 생성한 리포트는 만료 후에도 영구 열람 가능. 새 생성만 잠김

### 4.2 구독 상태와 전이

- **귀속**: 앱 계정. RevenueCat appUserID = 회원 ID. 무료 1회 이력은 서버에 기록 (기기 변경·재설치에도 유지)
- 상태: 무료 / 구독 활성 / 만료. 해지 시 결제 기간 말까지 혜택 유지, grace period·환불 처리는 스토어(RevenueCat) 기본 정책을 따름 (확정)
- 계정 삭제 후 재가입 시 무료 1회는 리셋되지 않도록 서버에서 방어 (확정 — 탈퇴-재가입 남용 방지, 구체 방식은 서버 설계 시 결정)

### 4.3 광고 제거

- 구독 활성 상태면 배너·전면 광고 전체 미노출. 만료 시 광고 복귀
- 구독 상태는 로컬 캐시하여 오프라인·앱 시작 직후에도 광고 미노출 유지 (확정)

### 4.4 페이월

- 진입점: ① AI 분석 화면에서 무료 1회 소진 후 생성 시도 시 ② 설정 내 구독 메뉴 ③ (Should 출시 후) 프리미엄 테마 선택 시
- 페이월에는 월/연 플랜과 "공개 예정 혜택"(테마·꾸미기) 명시

## 5. 데이터 및 시스템 (확정)

### 엔티티

| 엔티티 | 핵심 내용 | 비고 |
|---|---|---|
| Member (기존) | 회원 ID | RevenueCat appUserID로 연결 |
| Answer (기존) | 일일 답변 기록 | 리포트의 분석 재료 |
| AnalysisReport (신규) | 종류(사고패턴/따뜻한 회고), 대상 답변 ID 10~15개, 본문, 생성일시, 상태(생성중/완료/실패) | 본인만 열람, 영구 보존 |
| ReportQuota (신규) | 회원별 월 생성 횟수, 무료 1회 사용 여부 | 서버 기록 (재설치 무관) |

### 외부 연동

- **RevenueCat** (신규 도입, 사용자 승인됨): IAP 구매·복원·구독 상태 관리
- **AI 분석 서버**: 기존 "서버 연동 대기" 건이 이 기획의 Must로 편입
- **FCM 푸시** (기존): 리포트 완성 알림, (Should) 생성 유도 알림

### 시스템 결정

- **구독 검증은 서버에서.** RevenueCat webhook으로 서버가 구독 상태를 보유하고, 리포트 생성 API가 서버에서 권한·쿼터를 확인. 클라이언트 조작으로 AI 비용 유발 불가
- **리포트 생성은 비동기.** 요청 후 사용자는 앱을 자유롭게 사용, 완성되면 푸시로 복귀 유도. 생성 상태(생성중/완료/실패)를 AnalysisReport가 보유
- 비기능: AI 호출 비용은 월 생성 한도로 통제. 트래픽 규모 특이사항 없음

## 6. 마일스톤 (확정)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M1** | AI 리포트 기본 동작 — 서버 생성 API, 기록 선택(10~15개) UI, 비동기 생성 + 완성 푸시, 열람 화면, 무료 1회 로직 | 무료 사용자가 기록 선택 → 생성 → 푸시 → 열람 E2E 1회 성공 |
| **M2** | 결제 — RevenueCat 연동(월+연 플랜), 페이월, 구매 복원, 서버 webhook 검증, 설정 내 구독 상태 표시 | 샌드박스 결제로 구독자가 월 한도(10회) 내 생성 가능 |
| **M3** | 구독자 광고 제거 (배너·전면 전체) | 구독 시 광고 미노출, 만료 시 복귀 확인 |
| **M4** (출시 후) | 생성 유도 푸시 알림, 테마·꾸미기 | 별도 기획으로 상세화 |

## 7. 오픈 이슈

1. **가격**: 월/연 구체 금액 미정. 출시 직전 경쟁 앱(자기기록/저널링류) 가격 조사 후 확정
2. **전환율 목표치**: 성공 기준은 "구독 전환율"로 확정했으나 구체 목표 %와 측정 기간은 미정 (벤치마크 1~3% 참고)
3. **테마·꾸미기 상세**: M4 시점에 별도 기획 필요 (테마 종류, 앱 아이콘 변경 범위 등) — UI/UX 설계는 `/ux-spec` 후보
